### Redis
remote dictionary server 远程字典服务器，是一个基于内存的KV存储系统
把redis当成一个数据库，KV就是键值对，通过key快速查到对应的value值，存在**内存**中，单线程，键值对的形式存储，比较快，比sql查的快多了。
- **流程**：
	第一次查询时，先从redis中查找，如果没有找到再从mysql数据库中找，然后把结果存到redis中，并设置过期时间，后续相同分布式Session问题的查询就能直接从redis返回结果
- **分布式Session问题**：
	- 用户的请求发到不同的服务器的时候，**由于Session数据未共享，导致服务器无法识别用户身份**，所以可以使用redis解决。让所有请求来了，服务器都去查中央大数据库（redis集群）
- **分布式锁**：
	- 优秀的分布式锁需要有互斥性（一台机器只有一个线程能拿到锁）；防死锁（有超时释放机制）；容错性
		- 让多个服务器都从redis去获取锁资源，谁先拿到锁谁就能操作，其他人排队等待
- **Redis常见问题
	- **缓存穿透问题**：
		- 有用户恶意一直查询不存在的数据，绕过缓存，直接攻击数据库
		- 解决方案：即使mysql查询结果为空，仍将空缓存存在redis里，并且设置一个较短的过期时间，后续相同请求回直接命中缓存的空值
	- **缓存击穿**：
		- 热门数据突然过期，大量请求全都涌向数据库。
		- 解决方案：可以用互斥锁让请求排队一个一个来，第一个请求用来重建缓存，其他的就可以直接查redis了
	- **缓存雪崩**：
		- 大量缓存同时过期，数据库瞬间压力巨大
		- 解决方案：给数据库加上随机值，避免同时失效
		 ![diagram](../assets/pasted-image-20260909133352.png)
	- **redis本身也扛不住多并发**：
		- 建立多级缓存，从服务器本地缓存，到redis分布式缓存，再到数据库
		- 缓存预热：大促活动之前提前把热门商品数据加载到redis中
- **生产实践**：
	- **如何防止数据丢失**：
		两种持久化方案：
		1. **RDB快照**，定期把内存数据保存到硬盘，像拍照一样
		2. **AOF日志**，把每个写操作都记录下来，像记日记，数据更安全但是恢复比较慢
	- **Redis服务器挂了怎么办：**
		要部署**主从集群**，主节点负责写数据，从节点实时同步主节点的数据。主节点挂了，从节点立即顶上
		![diagram](../assets/pasted-image-20260909134232.png)
	- **主节点挂了，谁来决定哪个从节点升级**
		用**哨兵机制**，实时监控redis集群的健康状态
		![diagram](../assets/pasted-image-20260909134401.png)





##### HTTP
- 请求：
	curl -v 'http://......' ：不仅访问还把响应的所有内容都发送过来
```
	请求行
	请求头-H...(不自己定义的就会自动定义)
		常见请求头：
		1.HOST：我找哪台机器
		2.user-Agent：我是哪个浏览器/机器...
		3.Authorization：身份凭证，apikey就在里面
		4.cookie
	空行
	请求体-d...（curl默认发get，但是如果有-d有请求体要提交就变成post）
	
```
![diagram](../assets/pasted-image-20260908204215.png)
- 响应：
```
状态行：有状态码
	egHTTP/1.2 200 OK
	4开头是请求方的问题，5开头是服务方问题
响应头：
	content-type必写
空行
响应体
```
